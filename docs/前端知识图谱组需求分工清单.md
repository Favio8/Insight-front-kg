# 前端知识图谱组任务清单

## 1. 使用方式

这份文档只罗列前端和知识图谱组需要完成的任务，不写人员安排。组内可以根据任务编号自行分配。

每条任务按以下口径记录：

```text
任务编号
当前状态
任务内容
输入
输出
验收标准
风险或备注
```

状态建议统一使用：

```text
已完成
待实机验证
待联调
进行中
未开始
阻塞
```

## 3. T1 mock 数据闭环

当前状态：已完成，待 Neo4j 实机验证。

任务内容：

```text
用新能源汽车 mock 数据跑通 insight_payload -> graph_payload -> Neo4j -> 前端图谱展示。
```

输入：

```text
samples/new-energy-insight-payload.json
frontend/public/samples/new-energy-insight-payload.json
```

输出：

```text
graph_payload
visualization_payload
前端图谱展示
```

验收标准：

- 前端可以点击“加载 mock”。
- `/api/graph/build` 可生成 `graph_payload`。
- `/api/graph/ingest` 在 Neo4j 正常时返回 `persistence_meta.status=persisted`。
- `graph_nodes.length > 0`
- `company_edges.length > 0`
- `profile_edges.length > 0`
- `evidence_chunks.length > 0`

风险或备注：

- 如果 Neo4j 没启动，主流程会返回 `failed`，这是预期行为。

## 4. T2 KG 服务接口

当前状态：已完成。

任务内容：

```text
提供前端和后端 Agent 组都能调用的知识图谱 REST 接口。
```

接口清单：

```text
GET  /health
POST /api/graph/build
POST /api/graph/ingest
GET  /api/graph/visualization
POST /api/graph/persist
POST /api/graph/build-and-persist
```

主接口：

```text
POST /api/graph/ingest
```

输出：

```text
graph_payload
visualization_payload
persistence_meta
```

验收标准：

- `/health` 返回 `status=ok`。
- `/api/graph/build` 返回 `graph_payload` 和 `validation_meta`。
- `/api/graph/ingest` 完成生成、校验、入库和查询转换。
- Neo4j 缺配置时返回 `failed`，包含 `reason`、`error_type`、`trace_id`。
- 显式设置 `KG_ALLOW_GRAPH_PAYLOAD_FALLBACK=true` 时才允许 `skipped`。

风险或备注：

- `/api/graph/build` 只用于 debug，不是最终主链路。

## 5. T3 graph_payload schema 校验

当前状态：已完成。

任务内容：

```text
在 graph_payload 写入 Neo4j 前完成结构校验，避免脏数据进入主存储。
```

输入：

```text
graph_payload
```

输出：

```text
validation_meta
或 persistence_meta.status=failed
```

验收标准：

- `graph_nodes` 必须是数组。
- `relation_candidates` 必须是数组。
- `graph_edges` 必须是数组。
- `evidence_chunks` 必须是数组。
- `graph_edges` 只允许 `verified` 和 `strong_candidate`。
- `graph_edges[].head` 和 `graph_edges[].tail` 必须能找到对应节点。
- 校验失败时不调用 Neo4j 写入。

风险或备注：

- 后端真实数据接入时，如果字段结构变化，需要同步更新校验规则。

## 6. T4 Neo4j 主存储写入

当前状态：代码已完成，待实机验证。

任务内容：

```text
把 graph_payload 作为中间格式，校验通过后强制写入 Neo4j 主存储。
```

输入：

```text
graph_payload
trace_id
project_id
document_id
version
```

输出：

```text
Neo4j 节点
Neo4j 明确关系类型
RelationFact
EvidenceChunk
Source
persistence_meta
```

验收标准：

- 写入使用事务。
- 节点和关系使用 `MERGE`。
- 已创建唯一约束和查询索引。
- 成功返回 `status=persisted`。
- 成功返回 `node_count`、`relation_count`、`trace_id`、`created_at`。
- 失败返回 `status=failed`、`reason`、`error_type`、`trace_id`。
- 不默认返回 `skipped`。

验证 Cypher：

```cypher
MATCH (a)-[r]->(b)
WHERE r.rel_id IS NOT NULL
RETURN a.name AS head, type(r) AS relation, b.name AS tail, r.confidence AS confidence
LIMIT 25;
```

风险或备注：

- 真实 Neo4j 未启动时无法完成 persisted 验收。
- 后续如果同一实体跨项目复用，需要继续完善 `project_id` 维度的隔离策略。

## 8. T6 前端图谱结果区

当前状态：已完成，待浏览器实机验收。

任务内容：

```text
提供独立前端图谱工作台，用于 mock 验证、后端 JSON 粘贴和 Neo4j 主链路展示。
```

功能清单：

- 加载 mock。
- 粘贴后端 JSON。
- debug 生成 `graph_payload`。
- 主流程调用 `/api/graph/ingest`。
- 显示节点数、公司边、画像边、入库状态。
- 展示产业链摘要。
- 展示公司关系图。
- 点击公司节点展开画像关系。
- 点击关系边展示证据、来源、置信度和状态。
- Neo4j 失败时显示 `failed`、原因和 `trace_id`。

验收标准：

- `npm run build` 通过。
- 页面能打开 `http://localhost:3001`。
- 点击“生成并写入 Neo4j”后，图谱不空白。
- 点击节点和边有响应。
- 空状态和失败态信息清楚。

风险或备注：

- 当前前端只覆盖图谱工作台，不是最终完整 Web 应用页面。

## 9. T7 后端 Agent 组对接

当前状态：文档已完成，待联调。

任务内容：

```text
明确后端 Agent 组输出 insight_payload 的字段要求，并用真实输出跑通 /api/graph/ingest。
```

后端必须提供：

```text
task_profile
chain_skeleton
segment_companies
company_cards
source_index
```

重点字段：

```text
company_cards[].relationship_clues
company_cards[].field_evidence
company_cards[].key_sources
company_cards[].evidence_excerpts
source_index[].source_grade
```

验收标准：

- 后端真实 `insight_payload` 可以直接传给 `/api/graph/ingest`。
- 结构化 `relationship_clues` 能生成非空 `company_edges`。
- 字段级 `field_evidence` 能生成有证据的 `profile_edges`。
- 来源链接和来源等级能显示在前端边详情里。

风险或备注：

- 如果后端字段缺失，图谱可以生成但边或证据可能不足。
- 如果后端输出关系线索不结构化，公司关系边可能为空。

## 10. T8 第一周演示路径

当前状态：文档已完成，待完整跑通并记录。

任务内容：

```text
形成一个可复现的第一周演示流程，用 mock 数据展示知识图谱端到端闭环。
```

演示步骤：

```text
1. 启动 Neo4j。
2. 配置 NEO4J_URI、NEO4J_USER、NEO4J_PASSWORD。
3. 启动 KG 服务。
4. 启动前端。
5. 打开 http://localhost:3001。
6. 点击“加载 mock”。
7. 点击“生成并写入 Neo4j”。
8. 展示 persisted、trace_id、节点数、公司边、画像边、证据片段数量。
9. 点击公司节点，展示画像关系。
10. 点击关系边，展示证据文本和来源链接。
11. 在 Neo4j Browser 按 trace_id 查询节点、关系和证据。
12. 说明后端 Agent 组接入时只需要替换 insight_payload。
```

验收标准：

- 演示全程不依赖真实搜索。
- 演示全程可以解释 `insight_payload -> graph_payload -> Neo4j -> 前端图谱`。
- 能展示成功状态和失败状态。
- 能说明 `graph_payload` 是中间格式，Neo4j 是主存储。

风险或备注：

- 演示当天必须提前确认 Docker、Neo4j、KG 服务、前端端口没有冲突。
