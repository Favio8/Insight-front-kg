# 第一周需求列表

## 1. 第一周总目标

把 `Insight-front-kg` 做成可直接演示、可和后端 Agent 组对接的知识图谱前端工作台。

前端和知识图谱小组内部具体分工见：

```text
docs/前端知识图谱组需求分工清单.md
```

本周完成后，应能稳定跑通：

```text
mock insight_payload
-> KG 服务生成 graph_payload
-> schema 校验
-> Neo4j 主存储事务写入
-> Neo4j 查询 visualization_payload
-> 前端展示知识图谱
-> 记录验证结果
```

当前验收口径：

- 可以先用 mock 数据跑通。
- `graph_payload` 保留为中间交换、调试、审计和重试格式。
- Neo4j 是图谱主存储，不再是默认可选项。
- `skipped` 只允许在显式配置 `KG_ALLOW_GRAPH_PAYLOAD_FALLBACK=true` 时出现。
- GraphRAG、CEO 决策问答、复杂图查询 API 不作为第一周完成项。

## 3. R1 mock 数据闭环

优先级：P0

目标：

```text
使用固定 mock insight_payload 验证图谱生成、schema 校验、Neo4j 入库和前端展示闭环。
```

输入：

```text
samples/new-energy-insight-payload.json
frontend/public/samples/new-energy-insight-payload.json
```

功能要求：

- 前端可以加载“新能源汽车”mock 数据。
- KG 服务可以根据 mock `insight_payload` 生成 `graph_payload`。
- mock 数据必须包含 `task_profile`、`chain_skeleton`、`segment_companies`、`company_cards`、`source_index`。
- mock 数据必须包含结构化 `relationship_clues`。
- mock 数据必须包含字段级 `field_evidence`。

验收标准：

- `graph_nodes.length > 0`
- `company_edges.length > 0`
- `profile_edges.length > 0`
- `evidence_chunks.length > 0`
- `/api/graph/ingest` 返回 `persistence_meta.status=persisted`
- 前端点击“生成并写入 Neo4j”后能看到产业关系图。

当前基线结果：

```text
graph_nodes=43
company_edges=2
profile_edges=18
evidence_chunks=27
```

## 4. R2 KG 服务接口

优先级：P0

目标：

```text
提供后端 Agent 组和前端都能调用的 REST 图谱服务。
```

服务地址：

```text
http://localhost:8008
```

接口要求：

```text
GET  /health
POST /api/graph/ingest
GET  /api/graph/visualization
POST /api/graph/build
POST /api/graph/persist
POST /api/graph/build-and-persist
```

接口说明：

- `/api/graph/ingest` 是推荐主入口：输入 `insight_payload`，输出 `graph_payload`、`visualization_payload` 和 `persistence_meta`。
- `/api/graph/visualization` 从 Neo4j 按 `trace_id` 或 `project_id` 查询前端展示数据。
- `/api/graph/build` 只生成 `graph_payload`，作为 debug/兼容接口。
- `/api/graph/persist` 输入 `graph_payload`，默认强制写 Neo4j。
- `/api/graph/build-and-persist` 兼容旧调用，但语义改为强制写 Neo4j。

验收标准：

- `/health` 返回 `status=ok`。
- `/api/graph/build` 能处理 mock `insight_payload`。
- `/api/graph/ingest` 成功时返回 `status=persisted`。
- Neo4j 未配置时返回 `status=failed`，包含 `reason`、`error_type`、`trace_id`。
- 显式开启 `KG_ALLOW_GRAPH_PAYLOAD_FALLBACK=true` 时，才允许 `status=skipped`。


## 5. R3 Neo4j 主存储

优先级：P0

目标：

```text
Neo4j 承担最终知识图谱主存储，支撑后续查询、展示、证据追溯和推理。
```

Neo4j 启动命令：

```powershell
cd D:\AAA_Favio_2026\AI_exploring\DigitalChina\Insight-front-kg
docker compose -f docker-compose.neo4j.yml up -d
```

环境变量：

```powershell
$env:NEO4J_URI="bolt://localhost:7687"
$env:NEO4J_USER="neo4j"
$env:NEO4J_PASSWORD="your_password"
$env:KG_GRAPH_VERSION="v1"
```

验收标准：

- 写入前执行 `graph_payload` schema 校验。
- 使用事务写入，避免部分节点或部分关系成功。
- 节点、证据、关系使用 `MERGE`，避免重复实体。
- 成功时返回 `persistence_meta.status=persisted`。
- 成功时返回节点数量、关系数量、`trace_id`、`created_at`。
- 失败时返回 `persistence_meta.status=failed`，不静默跳过。
- 节点和关系保留推理预留字段：`entity_id`、`entity_type`、`relation_type`、`source`、`evidence`、`confidence`、`project_id`、`document_id`、`version`、`created_at`、`updated_at`。

## 6. R4 前端图谱结果区

优先级：P0

目标：

```text
前端作为独立图谱工作台运行，默认展示 Neo4j 查询结果。
```

页面地址：


## 7. R5 后端 Agent 组对接

优先级：P0

目标：

```text
明确后端 Agent 组需要交付的 insight_payload 字段，保证后续真实数据可以接入。
```

当前状态：

```text
协议适配已完成，待后端真实产业输出联调。
```

已确认主后端输出来源：

```text
POST /report/
GET  /api/reports/{research_id}
GET  /outputs/<task>.insight.json
WS   /ws -> type=path -> output.insight_payload
```

后端输入要求：

```text
task_profile.industry
chain_skeleton
segment_companies
company_cards
source_index
```

关键字段要求：

```text
company_cards[].relationship_clues
company_cards[].field_evidence
company_cards[].key_sources
company_cards[].evidence_excerpts
source_index[].source_grade
```

结构化 `relationship_clues` 示例：

```text
目标企业=比亚迪；关系层级=industry_template；关系名称=动力电池供应；方向=本企业->目标企业；证据=宁德时代为比亚迪提供动力电池相关产品。；来源=https://example.com/catl-byd；来源等级=A；解释=宁德时代向比亚迪提供动力电池相关产品
```

验收标准：

- 后端给出的 `insight_payload` 可以直接传给 `/api/graph/ingest`。
- 后端 `/report/` 完整响应可以被 KG 服务和前端导入弹窗自动解包。
- 后端 WebSocket `path` 消息可以被 KG 服务和前端导入弹窗自动解包。
- 后端 `/api/reports/{research_id}` 历史报告结构可以被 KG 服务和前端导入弹窗自动解包。
- 前端可以按 report id、`outputs/*.insight.json` 路径或完整 URL 从主后端拉取结果。
- 后端给出的 `relationship_clues` 能生成非空 `company_edges`。
- 后端给出的 `field_evidence` 能支撑 `profile_edges` 的证据展示。
- 后端给出的 `source_index` 可以支撑证据来源展示。

对接文档：

```text
docs/api-contract.md
```

联调注意：

```powershell
$env:CORS_ALLOW_ORIGINS="http://localhost:3001,http://127.0.0.1:3001,http://localhost:3000,http://127.0.0.1:3000"
```

## 8. R6 第一周演示路径

优先级：P0

目标：

```text
形成一个可复现的第一周演示流程。
```

演示步骤：

```text
1. 启动 Neo4j。
2. 配置 NEO4J_URI、NEO4J_USER、NEO4J_PASSWORD。
3. 启动 KG 服务。
4. 启动前端。
5. 打开 http://localhost:3001。
6. 默认加载新能源汽车 mock，或通过“导入 JSON”拉取主后端 report id / insight_json 路径。
7. 点击“写入 Neo4j”。
8. 展示 persisted、trace_id、节点数、公司边、画像边、证据片段数量。
9. 点击公司节点，展示画像关系。
10. 点击关系边，展示证据文本和来源链接。
11. 在 Neo4j Browser 按 trace_id 查询节点、关系和证据。
12. 打开 docs/api-contract.md，说明后端 Agent 组需要输出哪些字段，以及如何提供 report id / insight_json 路径。
```

验收标准：

- 演示全程不依赖真实搜索。
- 演示全程可以解释 `insight_payload -> graph_payload -> Neo4j -> 前端图谱`。
- 能说明后端真实数据接入后替换的是 `insight_payload`。
- 能说明 `graph_payload` 是中间格式，Neo4j 是主存储。
